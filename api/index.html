결론부터 — 이 세 줄이면 됩니다

API는 "이 주소에, 이 방식으로 부탁하면, 이 모양으로 답해 줄게"라는 약속입니다.

  1. 1
    엔드포인트 = 주소(경로) + 메서드 한 쌍GET /equipments 는 "설비 목록 보여줘", POST /reports 는 "보고서 새로 만들어줘".
  2. 2
    요청은 시작줄 · 헤더 · 바디, 응답은 상태 코드 · 헤더 · 바디(JSON)2xx 성공, 4xx 보낸 쪽 문제, 5xx 받은 쪽 문제.
  3. 3
    FastAPI로 몇 줄이면 만들고, /docs에서 바로 시험문서(OpenAPI)가 저절로 생깁니다. 그 문서를 AI에게 주면 호출 코드도 정확해집니다.

APIApplication Programming Interface

프로그램이 다른 프로그램에게 일을 부탁하는 정해진 방법. 사람용 화면(UI)의 프로그램용 버전.

예) 측정 DB를 화면 대신 코드로 조회
클라이언트client

부탁하는 쪽. 브라우저, 파이썬 스크립트, 엑셀 매크로, 다른 서버도 될 수 있습니다.

예) 내 리포트 스크립트
서버server

부탁을 기다리다 처리해 주는 쪽. 늘 켜져 있는 프로그램.

예) 사내 측정 데이터 서버
요청request

클라이언트가 보내는 주문서 한 장. 주소 · 메서드 · 헤더 · (바디).

예) "EQ-03 어제 두께 주세요"
응답response

서버가 돌려주는 답 한 장. 상태 코드 · 헤더 · 바디.

예) 200 + 측정값 JSON
HTTPHyperText Transfer Protocol

요청 · 응답을 주고받는 공통 규칙. 웹 API 대부분이 이걸 씁니다. HTTPS는 암호화된 HTTP.

예) 주소가 https:// 로 시작
한 장씩 켜집니다. "서버"는 컴퓨터 한 대를 가리킬 때도, 그 위에서 도는 프로그램을 가리킬 때도 씁니다. 대화에선 대개 프로그램 쪽입니다. REST라는 말도 자주 들립니다 — "주소는 명사(자원), 행동은 메서드로" 같은 관례를 따르는 HTTP API를 부르는 이름입니다. 오늘 배우는 모양이 바로 그것입니다.
WORDS · URL 해부

주소 한 줄에 다섯 조각이 들어 있습니다

https://api.cmp.사내:8000/v1/equipments/EQ-03/thickness?day=2026-11-23&limit=10
스킴규칙 · https = 암호화
호스트어느 서버 (건물 주소)
포트그 서버의 몇 번 문 · 생략하면 https는 443
경로 (path)어느 창구 — 엔드포인트의 주소 부분
경로 파라미터경로 속 바뀌는 칸 — "어느 설비"
쿼리 파라미터? 뒤 키=값, &로 이음 — "조건 · 옵션"

경로 파라미터는 "무엇을"(EQ-03이라는 대상), 쿼리 파라미터는 "어떻게 · 얼마나"(날짜 조건, 10개만).

주소는 예시입니다. 브라우저 주소창에 보이는 그 URL과 같은 구조입니다. /v1/ 은 버전입니다. 나중에 형식을 바꿔도 v1을 쓰는 사람은 깨지지 않게 v2를 따로 엽니다.
WORDS · 엔드포인트

엔드포인트 = 메서드 + 경로 — 창구 하나

메서드경로하는 일
GET/v1/equipments설비 목록 보기
GET/v1/equipments/{eq}설비 하나 자세히
GET/v1/equipments/{eq}/thickness그 설비의 두께 측정값
POST/v1/reports보고서 새로 만들기
DELETE/v1/reports/{id}보고서 지우기
GET/health살아 있나? (와치독용)

경로는 명사

/getEquipmentList보다 /equipments. 동작은 메서드가 말합니다.

복수형 + 하나

목록은 /reports, 그중 하나는 /reports/17. 폴더와 파일처럼.

{ } = 자리 표시

{eq} 자리에 실제 값(EQ-03)이 들어갑니다.

같은 경로라도 메서드가 다르면 다른 창구입니다. GET /reports(목록 보기)와 POST /reports(새로 만들기)는 다른 엔드포인트입니다. /health는 로그와 모니터링 덱의 와치독이 부르는 창구입니다.

WORDS · 메서드 (HTTP 동사)

다섯 개의 동사 — 보기 · 만들기 · 바꾸기 · 지우기

메서드뜻식당으로데이터가 바뀌나두 번 보내면
GET보기 · 가져오기"메뉴 보여 주세요"안 바뀜같은 결과
POST새로 만들기 · 실행시키기"새 주문 넣을게요"바뀜두 개 생길 수 있음
PUT통째로 교체"주문을 이걸로 다시 써 주세요"바뀜같은 결과
PATCH일부만 수정"맵기만 덜하게요"바뀜대개 같은 결과
DELETE지우기"주문 취소요"바뀜이미 지워짐

브라우저 주소창 = GET

주소를 쳐서 열리는 건 전부 GET입니다. 그래서 GET은 아무것도 바꾸면 안 됩니다.

POST는 두 번 누르면 두 번

"보고서 만들기"를 재시도하면 보고서가 두 개. 재시도 로직을 붙일 땐 조심합니다.

"두 번 보내도 결과가 같은" 성질을 멱등(idempotent)이라고 부릅니다. GET · PUT · DELETE는 멱등, POST는 아닙니다. 로그 덱의 슈퍼바이저가 작업을 재시작할 때 POST가 중복 실행될 수 있다는 점과 이어집니다.
WORDS · 요청 한 장 해부

주문서는 세 부분 — 시작줄 · 헤더 · 바디

POST /v1/reports HTTP/1.1
Host: api.cmp.사내 Content-Type: application/json Authorization: Bearer eyJhbGciOi…(토큰)
{ "week": "W47", "equipments": ["EQ-02", "EQ-03"], "format": "pptx" }
시작줄메서드 + 경로. "어느 창구에 무슨 부탁"
헤더 (header)봉투 겉면의 메모. 내용 형식(Content-Type), 신분증(Authorization) 등 키: 값 줄들
바디 (body)봉투 속 내용물. 보통 JSON. GET은 대개 바디 없이 파라미터로.

빈 줄 하나가 헤더와 바디를 가릅니다. 우리가 직접 쓸 일은 없고, 라이브러리가 만들어 줍니다.

실제로 네트워크를 오가는 글자를 거의 그대로 보여 준 것입니다. 우리는 requests 같은 라이브러리로 "메서드, 주소, 헤더, 바디"만 넘기면 됩니다. 헤더 = 봉투 겉면, 바디 = 봉투 속. 이 비유 하나면 충분합니다.
WORDS · 응답과 JSON

답도 같은 모양 — 상태 코드 · 헤더 · 바디

HTTP/1.1 200 OK
Content-Type: application/json
{ "eq": "EQ-03", "day": "2026-11-23", "unit": "Å", "items": [ {"time": "08:10", "avg_thk": 4003.1}, {"time": "14:40", "avg_thk": 4007.9} ], "count": 2 }
JSONJavaScript Object Notation

API의 표준 바디 형식. { } 묶음, [ ] 목록, "키": 값.

필드 · 키field · key

"avg_thk"처럼 값에 붙은 이름. 엑셀의 열 이름.

스키마schema

"이 응답엔 이런 필드가 이런 타입으로 온다"는 모양 약속. 메뉴판의 사진.

JSON의 문법 함정(작은따옴표, 마지막 쉼표)은 파일 형식 덱에서 봤습니다. API에선 라이브러리가 만들어 주니 덜 신경 써도 됩니다. 파이썬에서는 response.json() 한 줄이면 딕셔너리 · 리스트로 바뀝니다.

첫 숫자만 봐도 누구 문제인지 압니다

2xx성공200 OK · 201 Created(만들어짐) · 204 No Content(성공, 돌려줄 것 없음)
3xx다른 곳으로301 · 302 — 주소가 옮겨짐. 라이브러리가 알아서 따라감
4xx보낸 쪽(나) 문제주소 · 입력 · 권한을 고치면 해결
5xx받은 쪽(서버) 문제내가 고칠 수 없음 → 기다리거나 담당자에게
코드뜻식당으로먼저 확인할 것
400 Bad Request요청 모양이 잘못됨주문서를 알아볼 수 없음JSON 형식 · 필수 값
401 Unauthorized누구신지 모름회원증 안 냄토큰 있나 · 만료됐나
403 Forbidden누군진 아는데 권한 없음VIP 전용 메뉴내 계정 권한
404 Not Found그런 창구 · 대상 없음없는 메뉴경로 오타 · EQ 이름
422 Unprocessable모양은 맞는데 값이 이상"김치찌개 -2인분"값의 타입 · 범위
500 · 503서버 내부 오류 · 잠시 불가주방 화재 · 재료 소진담당자 · 잠시 후 재시도
첫 자리만 기억하세요: 2 성공, 4 내 탓, 5 서버 탓. 4xx면 내 요청을 고치고, 5xx면 기다리거나 알립니다. 문제 장면의 401은 이 표 두 번째 줄 — 헤더에 토큰을 안 넣었던 것입니다.
⚠️ AUTH · 신분증은 헤더에

API 키 · 토큰은 비밀번호와 같다

API 키API key

"이 프로그램은 등록된 손님"이라는 긴 문자열. 보통 사람이 아니라 프로그램에 발급.

토큰token · Bearer

로그인하면 받는 임시 출입증. Authorization: Bearer 토큰으로 냅니다. 만료 시각이 있습니다.

401 vs 403

401 = 신분증이 없거나 틀림. 403 = 신분증은 맞는데 이 방 출입 권한이 없음.

headers = {"Authorization": "Bearer eyJhbGciOi…"}  # ❌ 코드에 박음
import os
token = os.environ["CMP_API_TOKEN"]   # ✅ 환경변수
headers = {"Authorization": f"Bearer {token}"}

절대 하지 말 것

키를 코드 · git · 메신저 · 로그 · AI 채팅에 붙이기. 새면 담당자에게 알리고 재발급.

API 키가 git에 올라가면 지워도 기록(히스토리)에 남습니다. 키를 폐기하고 새로 받는 게 유일한 해결책입니다. 환경변수 · .env는 터미널 덱에서 본 "쪽지"입니다.

세 가지 방법 — 브라우저 · 터미널 · 파이썬

🌐 브라우저 주소창

GET만. 주소를 치면 JSON이 그대로 보입니다. 가장 빠른 확인.

http://localhost:8000/v1/equipments

⌨️ PowerShell

JSON을 표처럼 보여 줍니다. (PowerShell의 curl은 다른 명령의 별명 — 진짜는 curl.exe)

Invoke-RestMethod `
  -Uri "http://localhost:8000/v1/equipments/EQ-03/thickness?day=2026-11-23" `
  -Headers @{ Authorization = "Bearer $env:CMP_API_TOKEN" }

🐍 파이썬 requests

스크립트 · 자동화에. 상태 코드부터 확인.

import os, requests
BASE  = "http://localhost:8000"
TOKEN = os.environ["CMP_API_TOKEN"]

r = requests.get(
    f"{BASE}/v1/equipments/EQ-03/thickness",
    params={"day": "2026-11-23"},
    headers={"Authorization": f"Bearer {TOKEN}"},
    timeout=10)
r.raise_for_status()  # 4xx·5xx면 에러
data = r.json()

timeout을 꼭. 없으면 서버가 답을 안 할 때 영원히 기다립니다 — 로그 덱의 "살아 있는데 멈춘" 장애가 바로 이것.

params=로 넘기면 requests가 ?day=... 를 알아서 붙여 줍니다(한글 · 특수문자 인코딩까지). raise_for_status()는 "2xx가 아니면 예외로 만들어 줘"입니다. 이게 없으면 404 응답을 정상 데이터처럼 처리하는 실수를 합니다.
② BUILD · FastAPI로 만들기

함수 하나 = 엔드포인트 하나

# main.py
from fastapi import FastAPI, HTTPException

app = FastAPI(title="CMP 두께 API")
DATA = {"EQ-03": [{"day": "2026-11-23", "avg_thk": 4005.5}]}

@app.get("/health")
def health():
    return {"status": "ok"}

@app.get("/v1/equipments/{eq}/thickness")
def thickness(eq: str, day: str | None = None, limit: int = 100):
    if eq not in DATA:
        raise HTTPException(status_code=404, detail=f"{eq} 없음")
    rows = [r for r in DATA[eq] if day is None or r["day"] == day]
    return {"eq": eq, "items": rows[:limit], "count": len(rows)}
GET + 경로 → @app.get("…")
{eq} → 경로 파라미터 eq
?day=&limit= → 나머지 함수 인자
return {…} → 200 + JSON
HTTPException(404) → 404 응답

from pydantic import BaseModel, Field

class ReportIn(BaseModel):          # 주문서 양식
    week: str = Field(pattern=r"^W\d{2}$")
    equipments: list[str]
    format: str = "pptx"

@app.post("/v1/reports", status_code=201)
def create_report(body: ReportIn):
    report_id = make_report(body.week, body.equipments)
    return {"id": report_id, "week": body.week}

검사를 손으로 안 짠다

필수 값 · 타입 · 형식이 틀리면 함수가 실행되기도 전에 422 + 어느 칸이 왜를 돌려줍니다.

BaseModel 클래스가 "주문서 양식"입니다. 이 양식이 /docs에도 그대로 나타나서, 부르는 사람이 무엇을 보내야 하는지 압니다. 새로 만들었다는 뜻으로 201을 돌려주는 것이 관례입니다.

🪧 엔드포인트 = 메서드 + 경로

경로는 명사, 동작은 GET · POST · PUT · PATCH · DELETE. 경로 파라미터는 "무엇을", 쿼리는 "어떻게".

2 성공 · 4 내 탓 · 5 서버 탓. 401은 신분증, 404는 주소, 422는 값.
