머리글 한 칸컬럼 (column)이름에 공백 대신 avg_thk처럼 밑줄을 씀

노란 세 줄이 오늘의 중심입니다. 이후 장에서 하나씩 실제 표로 봅니다. "원본 순서는 바뀌지 않음" — 엑셀 정렬은 시트 자체를 바꾸지만, SQL은 결과만 정렬해서 보여 줍니다. 원본이 안전하다는 장점입니다.
① SELECT · WHERE · 필터

"EQ-03의 측정값만 보여줘" — 한 문장입니다

SELECT day, eq, avg_thk     -- 어떤 열을
FROM   thk                   -- 어느 테이블에서
WHERE  eq = 'EQ-03';          -- 어떤 행만 (필터)

읽는 순서는 위에서 아래로

"thk 테이블에서, eq가 EQ-03인 행의, day · eq · avg_thk 열을."

thk — 결과는 초록 줄
dayeqavg_thk
11-18EQ-024021.5
11-18EQ-034012.3
11-19EQ-024030.1
11-19EQ-033998.7
11-19EQ-05NULL

조건을 더하려면 AND avg_thk > 4000. 엑셀 필터를 두 개 거는 것과 같습니다.

이 다섯 행짜리 표를 덱 끝까지 계속 씁니다. 숫자를 기억해 두면 뒤의 GROUP BY · JOIN · NULL 장에서 결과를 손으로 검산할 수 있습니다. 글자 값은 작은따옴표('EQ-03'), 숫자는 그대로. AI가 자주 헷갈리는 부분은 아닙니다만, 사람이 손으로 고칠 때 자주 틀립니다.
ORDER · 쓰는 순서 ≠ 실행 순서

SQL은 위에서부터 쓰지만, 컴퓨터는 FROM부터 실행합니다

① FROM어느 테이블에서 (JOIN 포함)
→
② WHERE행을 거른다
→
③ GROUP BY묶는다
→
④ HAVING묶음을 거른다
→
⑤ SELECT보여 줄 열을 고른다
→
⑥ ORDER BY정렬, 그다음 LIMIT

그래서 생기는 에러

SELECT AVG(avg_thk) AS m … WHERE m > 4000 → WHERE가 먼저라 m을 아직 모릅니다. 묶은 뒤 조건은 HAVING.

읽을 때도 이 순서로

AI가 쓴 긴 쿼리는 FROM → WHERE → GROUP BY 순서로 읽으면, 어떤 행이 남는지 따라가기 쉽습니다.

클릭할 때마다 한 단계씩. 입문자가 가장 많이 막히는 지점입니다 — "SELECT에서 만든 이름을 WHERE에서 왜 못 쓰지?" DB 종류에 따라 ORDER BY에서는 SELECT의 별칭을 쓸 수 있습니다(SELECT 다음에 실행되므로).
② GROUP BY · 피벗 테이블

"설비별 평균 두께" — 피벗과 똑같습니다

SELECT eq,
       COUNT(*)      AS n,        -- 행 개수
       AVG(avg_thk)  AS mean_thk  -- 평균
FROM   thk
GROUP BY eq                     -- 피벗의 "행" 칸
ORDER BY eq;

엑셀 피벗: 행 = eq, 값 = avg_thk의 평균 · 개수

결과
eqnmean_thk
EQ-0224025.8
EQ-0324005.5
EQ-051NULL

손으로 검산

EQ-02: (4021.5 + 4030.1) ÷ 2 = 4025.8 ✓ — 한 줄만 손계산해도 쿼리를 믿을 근거가 생깁니다.

클릭하면 결과가 한 줄씩 나옵니다. EQ-05의 평균이 NULL인 이유는 다음 장의 함정과 연결됩니다 — 측정값이 비어 있습니다. "한 줄만 손계산"이 이 덱의 검산 원칙입니다. AI가 쓴 쿼리를 다 읽을 수 없어도, 결과 한 줄은 확인할 수 있습니다.
③ JOIN · VLOOKUP

"라인 정보 붙여줘" — 짝이 없는 행을 어떻게 할지 정합니다

equipment — 설비 정보
eqline
EQ-02L1
EQ-03L2
EQ-04L2
SELECT t.day, t.eq, e.line, t.avg_thk
FROM   thk t
LEFT JOIN equipment e ON t.eq = e.eq;

INNER JOIN — 양쪽에 다 있는 것만

EQ-05는 설비 정보가 없어서 사라집니다. 결과 4행.

LEFT JOIN — 왼쪽은 전부 남김

측정 5행이 모두 남고, EQ-05의 line은 NULL. VLOOKUP의 #N/A와 같습니다.

EQ-04는?

측정이 없어서 어느 쪽 결과에도 안 나옵니다. "측정 안 한 설비"를 찾으려면 equipment를 왼쪽에 둡니다.

클릭할 때마다 하나씩. 핵심 질문은 "짝이 없는 행을 버릴 것인가, 남길 것인가"입니다. AI에게 JOIN을 시킬 때 이 한 문장을 꼭 붙이게 하세요: "설비 정보가 없는 측정값도 남겨줘(LEFT JOIN)".
⚠️ TRAP 1 · JOIN 뒤에 행이 불어난다

짝이 두 개면 행이 두 배 — 에러 없이 합계가 틀어집니다

equipment — EQ-03이 두 줄 (라인 이동 이력)
eqlinesince
EQ-02L12025-01
EQ-03L12025-01
EQ-03L22026-06
-- JOIN 전
SELECT COUNT(*) FROM thk WHERE eq IN ('EQ-02','EQ-03');   → 4
-- JOIN 후
SELECT COUNT(*) FROM thk t JOIN equipment e ON t.eq = e.eq; → 6

무엇이 틀어지나

EQ-03 측정 2행이 각각 두 번씩 붙어 4행이 됩니다. SUM · COUNT가 부풀고, 평균도 묶는 방식에 따라 틀어집니다.

지키는 습관

JOIN 전후로 COUNT(*)를 비교합니다. 늘었다면 오른쪽 테이블에 같은 키가 여러 줄 있다는 신호입니다.

고치는 방향

"현재 라인만"처럼 오른쪽을 한 줄로 줄인 뒤 JOIN합니다. AI에게는 "키가 중복이면 알려줘"를 붙입니다.

VLOOKUP은 첫 번째 짝 하나만 가져오지만, JOIN은 짝을 전부 붙입니다. 그래서 엑셀에 익숙한 사람일수록 이 함정에 빠집니다. "JOIN 전후 COUNT 비교"는 이 덱에서 가장 실용적인 습관입니다.
⚠️ TRAP 2 · 빈칸(NULL)은 0이 아닙니다

NULL은 "모름" — 계산에서 조용히 빠집니다

-- thk 5행 중 EQ-05의 avg_thk가 NULL
SELECT COUNT(*)        FROM thk;   → 5
SELECT COUNT(avg_thk)  FROM thk;   → 4   NULL은 안 셈
SELECT AVG(avg_thk)    FROM thk;   → 4015.65 ÷4로 계산

SELECT * FROM thk WHERE avg_thk = NULL;   → 0행 (!)
SELECT * FROM thk WHERE avg_thk IS NULL;  → 1행

평균에서 빠진다

측정 누락이 많으면, 평균은 "측정된 것만의 평균"이 됩니다. 의도와 다를 수 있습니다.

= NULL은 항상 거짓

"모름"과 같은지 물으면 답도 "모름". 빈칸 찾기는 반드시 IS NULL.

먼저 세어 본다

분석 전에 "열마다 NULL이 몇 개인지" 쿼리부터. 많으면 처리 방식을 사람이 정합니다.

(4021.5 + 4012.3 + 4030.1 + 3998.7) ÷ 4 = 4015.65 — 다섯 행이 아니라 네 행으로 나눕니다. "= NULL이 0행"은 에러가 안 나서 더 위험합니다. AI도 가끔 실수하는 부분이라 리뷰 포인트입니다.

결과 모양을 표로

원하는 열 이름을 적어 주면, AI가 "무엇을 묶고 무엇을 셀지" 헷갈리지 않습니다.

함정을 미리 말하기

"측정 없는 설비도", "가장 최근 줄만" — 앞의 두 함정을 규칙으로 막습니다.

실데이터는 조심

예시 행은 구조만 보이면 됩니다. 실제 값이 민감하면 바꿔서 붙입니다.

테이블 구조는 DB에서 바로 뽑을 수 있습니다(SQLite라면 .schema, 다른 DB는 information_schema). 세 번째 카드는 보안 약속과 연결됩니다. 실제 측정값이 회사 정보라면 사내 승인 도구에서만, 또는 값을 바꿔서.

CHECK · AI가 쓴 쿼리 검산 3종

쿼리를 다 못 읽어도, 결과는 확인할 수 있습니다

  • 1건수 — JOIN 전후, 필터 전후 COUNT(*)가 예상대로 변했나30초
  • 2한 줄 손계산 — 결과 중 한 묶음을 원본에서 직접 계산해 같은가2분
  • 3눈으로 10줄 — LIMIT 10으로 결과를 직접 보고, 이상한 값(NULL·0·음수)이 있나1분
  • +엑셀과 비교 — 지금까지 엑셀로 내던 숫자 하나와 맞춰 본다처음 한 번

이 검산을 AI에게 함께 시키면 됩니다. "쿼리와 함께 검산 쿼리 세 개도 줘."

클릭할 때마다 하나씩. 3분이면 끝나는 검산이 회의에서 틀린 숫자를 내는 사고를 막습니다. "엑셀과 비교"는 DB로 옮기는 첫 주에 꼭 합니다. 엑셀 쪽이 틀렸던 걸 발견하는 경우도 꽤 있습니다.

⚠️ SAFETY · 읽기 전용이 기본

WHERE 없는 UPDATE 한 줄이면, 전체가 바뀝니다

-- ❌ EQ-03만 고치려 했는데 WHERE를 빠뜨림
UPDATE thk SET avg_thk = 4000;   -- 전체 행이 4000
-- ✅ 바꾸기 전에, 같은 조건으로 먼저 세어 보기
SELECT COUNT(*) FROM thk
 WHERE eq = 'EQ-03' AND day = '11-19';          -- 1
BEGIN;
UPDATE thk SET avg_thk = 4000
 WHERE eq = 'EQ-03' AND day = '11-19';     -- 1 row affected 확인
COMMIT;   -- 예상과 다르면 ROLLBACK;

분석은 읽기 전용 계정으로

SELECT만 되는 계정이면, AI가 실수해도 데이터는 안전합니다.

바꾸는 문장은 사람이 실행

UPDATE · DELETE · DROP은 AI가 써도, 실행은 확인 후 사람이. 하네스의 ask 칸입니다.

트랜잭션 = 되돌릴 수 있는 구간

BEGIN 뒤에는 COMMIT 전까지 ROLLBACK으로 취소할 수 있습니다.

사내 DB라면 대부분 읽기 전용 계정이 따로 있습니다. 분석 용도로는 그걸 쓰도록 안내합니다. 트랜잭션 동작은 DB 종류와 설정(자동 커밋 여부)에 따라 다릅니다. 처음엔 연습용 SQLite 파일에서 해 보게 합니다.

PYTHON · 엑셀을 DB로 옮기기

설치 없이 시작 — SQLite 파일 하나면 DB입니다

import sqlite3
import pandas as pd

conn = sqlite3.connect("cmp.db")            # 파일 하나 = DB 하나

# 엑셀 시트 → 테이블
df = pd.read_excel("w47_측정.xlsx")
df.to_sql("thk", conn, if_exists="replace", index=False)

# SQL 결과 → 다시 표(DataFrame)
summary = pd.read_sql(
    "SELECT eq, AVG(avg_thk) AS mean_thk FROM thk GROUP BY eq",
    conn)
print(summary)

SQLite

서버가 필요 없는 DB. 파이썬에 기본으로 들어 있습니다. 혼자 · 소수가 쓰는 분석에 충분합니다.

사내 DB로 갈 때

여러 명이 동시에 쓰거나 대시보드가 붙으면, 사내 표준 DB(PostgreSQL · Oracle 등)로 옮깁니다. SQL은 거의 그대로입니다.

엑셀 → DB는 한 번만

매주 새 엑셀은 같은 테이블에 이어 붙이고(if_exists="append"), 질문은 SQL로.

read_excel에는 openpyxl 패키지가 필요합니다. 이 코드는 실습에서 그대로 씁니다. "replace"는 테이블을 통째로 새로 만들고, "append"는 이어 붙입니다. 매주 붙일 때 replace를 쓰면 지난주 데이터가 사라지니 주의.

정리

오늘 가져갈 습관 세 가지

1. 아는 엑셀 기능으로 번역한다

필터 = WHERE, 피벗 = GROUP BY, VLOOKUP = JOIN. 읽을 땐 FROM부터.

2. 행 수와 빈칸을 의심한다

JOIN 전후 COUNT, 분석 전 NULL 개수. 에러 없이 틀리는 두 함정입니다.

3. 읽기 전용으로 묻고, 결과로 검산한다

SELECT만 되는 계정, 건수 · 손계산 · 눈으로 10줄. 바꾸는 문장은 사람이 실행합니다.
