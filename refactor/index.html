DEFINITION · 리팩터링이란

방 정리처럼 — 물건은 그대로, 놓인 자리만 바꿉니다

🛠️ 기능 바꾸기

새 차트 추가, 계산 방식 변경, 버그 수정.

결과가 달라져야 성공입니다.

🧹 구조 바꾸기 (리팩터링)

파일 나누기, 이름 바꾸기, 복붙 합치기.

결과가 똑같아야 성공입니다.

❌ "차트 하나 추가하면서 코드도 좀 정리해줘" — 결과가 달라졌을 때 추가 때문인지 정리 때문인지 알 수 없습니다
✅ 먼저 정리 → 출력이 같은지 확인 → 커밋 → 그다음 차트 추가
이 덱에서 가장 중요한 한 장입니다. 성공 기준이 정반대인 두 일을 한 번에 하면 검증할 방법이 사라집니다. AI에게 기능을 시키면 "하는 김에" 정리까지 하는 경우가 많습니다. 그래서 "기능만, 정리는 하지 마"를 붙이는 습관도 같이 권합니다.
SIGNALS · 정리가 필요하다는 신호 여섯

코드에서 이런 냄새가 나면 정리할 때입니다

📏 긴 파일

한 파일이 수백 줄을 넘고, 화면 · 계산 · 파일 읽기가 섞여 있습니다.

📋 복붙

같은 계산이 여러 곳에. 한 곳을 고치면 나머지는 옛날 그대로.

🧵 긴 함수

함수 하나가 한 화면을 넘습니다. 이름으로 무엇을 하는지 설명할 수 없습니다.

🏷️ 의미 없는 이름

df2, temp, final_final. 읽는 사람이 매번 추리해야 합니다.

🔢 마법의 숫자

코드 곳곳의 4000, 0.03. 무슨 뜻인지, 어디를 다 바꿔야 하는지 모릅니다.

👻 죽은 코드

주석 처리된 옛 버전, 아무도 부르지 않는 함수. AI가 이걸 보고 헷갈립니다.

"코드 냄새(code smell)"라는 표현에서 온 목록입니다. 냄새가 난다고 다 고칠 필요는 없습니다 — 자주 고치는 곳부터 정리합니다. 여섯 번째(죽은 코드)는 AI 시대에 특히 해롭습니다. AI는 주석 처리된 옛 코드도 읽고 그걸 참고해 버릴 수 있습니다.
SAFETY NET · 골든 출력

"지금 결과"를 저장해 두면, 같은지 비교만 하면 됩니다

tests/test_golden.py — 정리 전 결과와 비교 (예시)

import pandas as pd
from report import build_report

def test_report_unchanged():
    # 정리 전에 한 번 저장해 둔 결과 = 골든
    golden = pd.read_csv("tests/golden/w47_report.csv")
    # 지금 코드로 같은 입력을 다시 계산
    now = build_report("tests/data/w47_raw.csv")
    pd.testing.assert_frame_equal(now, golden)
$ pytest
tests/test_golden.py .                1 passed

테스트를 모르는 사람의 테스트

"맞는 결과"를 정의할 필요 없이, "지금과 같은 결과"만 확인합니다.

입력도 고정

매주 바뀌는 실데이터 대신, 한 주치 사본을 tests/data/에 고정해 둡니다.

AI가 스스로 돌리게

"정리할 때마다 pytest를 돌리고, 실패하면 되돌려" — 하네스의 검증 칸입니다.

특성 테스트(characterization test), 골든 테스트라고 부르는 방법입니다. 지금 결과가 "맞는지"는 모르지만 "바뀌지 않았는지"는 확실히 알 수 있습니다 — 리팩터링에 딱 필요한 것입니다. pytest는 파이썬 테스트 도구, pandas.testing.assert_frame_equal은 표 두 개를 비교하는 함수입니다. 테스트 데이터에 민감한 실데이터를 쓰지 않도록 주의합니다.

THE LOOP · 정리 한 바퀴

작게 바꾸고, 비교하고, 커밋 — 계속 반복합니다

  • 0시작 전 커밋 — 언제든 돌아올 지점git
  • 1골든 저장 — 지금 결과를 tests/golden에한 번
  • 2한 가지만 정리 — 예: 복붙된 계산 하나를 함수로AI
  • 3비교 — pytest 통과? 실패하면 바로 되돌림검증
  • 4통과하면 커밋 — "refactor: 두께 평균 계산 함수로 합침"git
  • ↻2번으로 — 한 바퀴는 10분 안쪽이 적당반복
클릭할 때마다 한 단계씩. 핵심은 "한 바퀴를 작게"입니다. 작게 돌면 실패해도 무엇 때문인지 바로 알고, 되돌리는 비용도 작습니다. 커밋 메시지에 refactor:를 붙이면 나중에 "동작 변경이 없는 커밋"을 구분할 수 있습니다.

EXAMPLE 1 · 복붙을 함수 하나로

같은 계산 세 군데 → 한 곳에서만 고치면 되게

❌ 전 — 세 화면에 같은 계산이 복사됨

# 일간 화면
d = df[df.eq == eq]
d = d[d.thk < 999]
daily = d.groupby("day").thk.mean().round(1)
# 주간 화면 (거의 같음… 999 필터 빠짐!)
w = df[df.eq == eq]
weekly = w.groupby("week").thk.mean().round(1)
# 설비 비교 화면 (또 복사)
…

✅ 후 — 계산은 한 곳, 화면은 부르기만

def mean_thk(df, eq, by):
    """측정 실패(999)를 빼고 by별 평균 두께."""
    d = df[(df.eq == eq) & (df.thk < INVALID_THK)]
    return d.groupby(by).thk.mean().round(1)

daily  = mean_thk(df, eq, "day")
weekly = mean_thk(df, eq, "week")

정리하다 버그를 찾으면?

주간 화면에 999 필터가 빠져 있었습니다. 고치면 결과가 바뀝니다 — 정리 커밋과 따로, 버그 수정 커밋으로 남깁니다.

복붙을 합치다 보면 사본끼리 조금씩 다른 걸 발견합니다. 그게 버그인지 의도인지는 사람이 정해야 합니다. 골든 테스트는 이 차이를 잡아냅니다(주간 결과가 달라짐). 그래서 "정리"와 "버그 수정"을 다른 커밋으로 나눕니다 — 앞의 정의 장과 연결.
EXAMPLE 2 · 마법의 숫자를 설정으로

스펙이 바뀌면 파일 하나만 고치게

❌ 전 — 숫자가 코드 곳곳에

ok = (thk > 3950) & (thk < 4050)   # report.py
…
if nu > 3.0: alert()                # alert.py
…
ax.axhline(4050, color="r")          # chart.py

✅ 후 — config.yaml 한 곳

thickness:
  target: 4000        # Å
  lsl: 3950
  usl: 4050
uniformity_max: 3.0    # %
invalid_value: 999     # 측정 실패 표시

이름이 생기면 뜻이 생깁니다

4050보다 usl(규격 상한)이 읽기 쉽고, AI도 의미를 압니다.

한 곳만 고치면 끝

스펙이 바뀌어도 세 파일을 뒤질 필요가 없습니다. 놓쳐서 생기는 불일치가 사라집니다.

코드 밖에서 바꿀 수 있음

코드를 모르는 동료도 설정 파일의 숫자는 고칠 수 있습니다.

숫자는 예시입니다. 실제 규격값은 공정마다 다르고, 회사 정보일 수 있으니 설정 파일을 공유할 때 주의합니다. "invalid_value: 999"처럼 데이터의 사정을 설정에 남겨 두면, 데이터 분석 덱에서 말한 "AI에게 알려 줘야 하는 정보"가 코드에 자연스럽게 남습니다.
STRUCTURE · 파일 하나에서 폴더로

한 파일에 섞인 일을 역할별 서랍으로 나눕니다

전

report/
├─ main.py      # 3,020줄
├─ main_old.py
├─ test2.py
└─ 측정.xlsx

후

report/
├─ app.py               # 시작점 — 순서만 (40줄)
├─ config.yaml          # 숫자 · 경로
├─ core/                # 계산 — 화면도 파일도 모름
│  ├─ stats.py          #   mean_thk, sigma …
│  └─ rules.py          #   규격 판정
├─ loaders/             # 읽고 쓰기
│  ├─ load_csv.py
│  └─ save_report.py
├─ ui/                  # 화면 · 차트
│  └─ charts.py
└─ tests/               # 골든 · 테스트 데이터

한 번에 다 옮기지 않습니다. 가장 자주 고치는 부분부터 한 서랍씩, 매번 골든 비교.

정답 구조는 없습니다. 폴더 이름을 io/처럼 파이썬 기본 모듈과 같게 지으면 import가 꼬이니 피합니다. 기준은 "어떤 걸 고칠 때 어느 파일을 열면 되는지 바로 알 수 있나"입니다. main_old.py, test2.py 같은 파일은 git이 있으면 지워도 됩니다. 옛 버전은 git 기록에 남아 있습니다.
DIRECTION · 누가 누구를 아는가

계산(core)은 화면도 파일도 모르게 — 그래야 오래 갑니다

🖥️
ui/화면 · 차트
자주 바뀜
→
🧮
core/계산 · 규칙
가장 중요, 가장 안 바뀌어야 함
←
📂
loaders/CSV · DB · 엑셀
데이터 출처가 바뀜

화면을 바꿔도

Streamlit → React로 옮겨도 core는 그대로 씁니다.

출처를 바꿔도

CSV → DB로 바꿔도 loaders만 고치면 됩니다.

테스트가 쉬워짐

core는 표를 받아 표를 돌려줄 뿐이라, 골든 비교가 간단합니다.

화살표는 "누가 누구를 불러 쓰는가"입니다. ui와 loaders가 core를 부르고, core는 아무도 부르지 않습니다. AI에게 "core 폴더 안의 코드는 streamlit이나 파일 경로를 import하지 않게"라는 규칙 한 줄을 주면 이 구조가 유지됩니다 — CLAUDE.md 후보.
PROMPT · AI에게 리팩터링 시키는 법

"깔끔하게"는 금지어 — 범위 · 금지 · 검증을 줍니다

❌ "코드 전체를 깔끔하게 정리해줘"
→
✅ report.py의 평균 계산 복붙 3곳만 함수 하나로. 다른 파일 금지
❌ "구조를 개선해줘"
→
✅ 먼저 나눌 계획만 표로. 내가 고른 한 단계씩 진행
❌ "정리하면서 버그도 고쳐줘"
→
✅ 동작은 바꾸지 마. 이상한 곳을 찾으면 고치지 말고 목록으로만
❌ "다 했으면 알려줘"
→
✅ 단계마다 pytest 결과를 보여주고, 통과하면 커밋까지
클릭할 때마다 하나씩. 네 쌍 모두 "범위를 좁히고, 금지를 말하고, 검증을 요구"하는 구조입니다. 세 번째가 특히 중요합니다. AI는 정리하다 이상한 코드를 보면 "개선"해 버립니다. 그게 버그 수정이어도, 정리 커밋 안에 섞이면 안 됩니다.
⚠️ TRAPS · AI 리팩터링의 함정 셋

통과했다고 끝이 아닙니다 — 어떻게 통과했는지도 봅니다

🎭 몰래 바뀐 동작

"정리"라면서 반올림 자리, 정렬 순서, 빈칸 처리가 바뀝니다. 골든 비교가 없으면 아무도 모릅니다.

🌊 한 번에 전부

파일 20개를 한꺼번에 바꾸면, 실패했을 때 원인을 못 찾고 통째로 되돌리게 됩니다.

🧪 테스트를 고쳐서 통과

골든 파일을 새 결과로 덮어쓰거나, 실패하는 테스트를 지워서 "통과"시킵니다.

막는 법 — 권한

tests/golden/은 deny로 막아 AI가 못 고치게 합니다.

막는 법 — 리뷰

diff에 테스트 파일 변경이 보이면 반드시 이유를 묻습니다.

세 번째 함정이 가장 교묘합니다. AI는 "테스트를 통과시켜라"는 목표를 가장 쉬운 방법으로 달성하려 할 수 있습니다. 골든 폴더를 deny로 막는 건 하네스 덱의 ③ 권한 칸을 그대로 쓴 예입니다.

리팩터링을 할 거야. 동작은 절대 바꾸지 마.
1) 지금 상태를 커밋
2) 대표 입력 하나로 지금 결과를 tests/golden에 저장하고
   같은지 비교하는 pytest 하나 만들기
3) 복붙된 코드 중 가장 많이 반복된 것 하나만 함수로
4) pytest 결과를 보여주고, 통과하면 커밋
이상한 코드를 발견하면 고치지 말고 목록으로만.

✅ 완료 기준

  • 정리 전후로 커밋이 두 개 있다
  • 골든 비교 테스트가 통과했다
  • diff에 테스트·골든 파일 변경이 없다

🧯 막히면

결과가 매번 달라서 골든이 안 맞으면(현재 시각, 랜덤 등), "결과에서 날짜·시각 열은 비교에서 빼줘"를 덧붙입니다. git이 없다면 폴더 사본으로 대신합니다.

20분. 세 번째 완료 기준이 함정 장의 "테스트를 고쳐서 통과"를 확인하는 장치입니다. "이상한 코드 목록"은 다음 작업(버그 수정)의 할 일 목록이 됩니다.
정리

오늘 가져갈 습관 세 가지

1. 기능과 정리를 섞지 않는다

기능은 결과가 달라져야, 정리는 결과가 같아야 성공입니다.

2. 골든 저장 → 작게 정리 → 비교 → 커밋

한 바퀴 10분. 실패하면 바로 되돌립니다.

3. AI에게는 범위 · 금지 · 검증

"깔끔하게"는 금지어. 테스트와 골든은 AI가 못 고치게 막아 둡니다.

세 습관으로 마무리. 다음 단계로 "사람이 리뷰하는 법" 덱을 안내하고 Q&A.
