결론부터 — 이 세 줄이면 됩니다

파이썬 문제의 대부분은 코드가 아니라 "어느 파이썬, 어느 패키지 버전"의 문제입니다.

  1. 1
    프로젝트마다 가상환경(.venv) 하나공용 파이썬에 다 깔면 프로젝트끼리 버전이 부딪힙니다.

  3. 3

설비마다 전용 지그 · 키트를 두는 것과 같습니다. 공용 공구함은 편하지만, 누가 바꿨는지 아무도 모릅니다.

① VENV · 만들고 켜기

세 줄이면 상자가 생깁니다 — 켜지면 (.venv)가 붙습니다

PS C:\…\cmp-report> python -m venv .venv          # 1. 만들기 (한 번)
PS C:\…\cmp-report> .venv\Scripts\Activate.ps1   # 2. 켜기 (창마다)
(.venv) PS C:\…\cmp-report> python -m pip install pandas
(.venv) PS C:\…\cmp-report> deactivate                 # 3. 끄기

# macOS · Linux
python3 -m venv .venv
source .venv/bin/activate

⚠️ PowerShell이 막을 때

…Activate.ps1 파일을 로드할 수 없습니다. 이 시스템에서 스크립트를 실행할 수 없으므로…

  • 1Set-ExecutionPolicy RemoteSigned -Scope CurrentUser내 계정만
  • 2회사 정책으로 막히면 cmd에서 .venv\Scripts\activate.bat우회
  • 3켜지 않고 .venv\Scripts\python.exe app.py직접 지정
"켜기"는 창마다 해야 합니다. 새 터미널을 열면 (.venv) 표시가 없는 상태로 돌아갑니다 — 문제 장면 3번의 흔한 원인. 회사 PC에서는 실행 정책 변경이 그룹 정책으로 막혀 있을 수 있습니다. 그럴 땐 3번처럼 상자 안 파이썬을 직접 부르는 게 가장 확실합니다.
① VENV · 상자 안에는

.venv는 일회용입니다 — 옮기지 말고, 다시 만드세요

cmp-report/
├─ .venv/                  상자 — git에 안 올림
│  ├─ Scripts/python.exe   상자 전용 파이썬
│  ├─ Scripts/pip.exe
│  └─ Lib/site-packages/   설치한 패키지가 여기로
├─ requirements.txt        목록 — git에 올림
├─ .gitignore              .venv/ 한 줄
└─ report.py

올리는 건 목록, 상자가 아니다

.venv는 수백 MB에 PC마다 경로가 박혀 있습니다. 동료는 목록으로 자기 상자를 만듭니다.

이상하면 지우고 다시

꼬였을 때 고치려 애쓰기보다 .venv 폴더를 지우고 두 줄 — 만들기 · 목록 설치 — 이 빠릅니다.

폴더 이름은 .venv

VS Code · 대부분 도구가 이 이름을 자동으로 알아봅니다.

"상자는 일회용, 목록이 진짜"가 이 장의 한 문장입니다. 상자를 zip으로 동료에게 보내면 대개 안 돕니다(경로가 다름).
② PIP · 설치는 이렇게

pip 대신 python -m pip — "이 파이썬에" 깔라는 뜻

명령뜻
python -m pip install pandas설치 (최신)
python -m pip install "pandas==2.2.3"정확히 이 버전
python -m pip list이 상자에 뭐가 있나
python -m pip show pandas버전 · 설치 위치

python -m pip install -r requirements.txt목록대로 한 번에

왜 python -m?

그냥 pip은 PATH에서 먼저 찾은 pip — 다른 파이썬의 pip일 수 있습니다. python -m pip은 지금 이 python에 붙은 pip입니다.

sudo · --user · 관리자 권한

"권한이 없다"고 관리자 권한으로 공용 파이썬에 까는 건 문제를 키웁니다. 상자를 먼저 켜세요.

터미널 덱의 PATH 이야기와 같습니다. python과 pip이 서로 다른 설치에서 올 수 있습니다. python -m pip는 길지만, 한 번 습관이 되면 "깔았는데 없다"가 사라집니다.

2.2.3
주(major)바뀌면 기존 코드가 깨질 수 있음 — 1.5 → 2.0에서 append가 사라짐

freeze는 딸려 온 패키지까지 수십 줄을 적습니다. 처음엔 그대로 두는 게 안전하고, 정리는 AI에게 "직접 import하는 것만 남겨줘".

버전을 안 적으면 설치하는 날의 최신이 깔립니다. 그래서 "어제는 됐는데" — 어제와 오늘 최신이 다릅니다. 버전 숫자는 세 칸. 첫 칸이 바뀌는 업그레이드는 "깨질 수 있다"는 경고로 읽으면 됩니다.
⚠️ CAUSES · "어제는 됐는데"의 범인 다섯

대부분 다른 상자에서 돌고 있습니다

  • 1새 터미널 — 상자를 안 켠 창에서 실행했다(.venv) 확인
  • 2VS Code 인터프리터 — ▶ 버튼이 다른 파이썬을 쓴다오른쪽 아래
  • 3버전 미고정 — 다시 설치하는 날 최신이 들어왔다== 고정
  • 4파이썬 자체 버전 — 3.8 서버 vs 3.12 내 PCpy -3.11
  • 5파일 이름 충돌 — 내 파일 이름이 pandas.py · json.py이름 바꾸기

5번은 의외로 흔합니다. 파이썬은 내 폴더의 파일을 먼저 import합니다. 진짜 pandas 대신 내 pandas.py가 불려요.

클릭할 때마다 하나씩. 1 · 2번이 절반 이상입니다. 다음 장의 진단 세 줄로 1 · 2 · 4번은 바로 가려집니다.

INTRANET · 인터넷이 막혀 있을 때

사내 미러를 가리키거나, 바퀴(wheel) 파일을 들고 들어갑니다

A. 사내 PyPI 미러가 있으면

# 한 번 설정 (주소는 인프라 담당에게)
python -m pip config set global.index-url https://pypi.사내미러/simple
python -m pip config set global.trusted-host pypi.사내미러
# 저장 위치: %APPDATA%\pip\pip.ini

B. 없으면 — 밖에서 받아 들고 오기

# ① 인터넷 되는 PC (같은 OS · 같은 파이썬 버전)
python -m pip download -r requirements.txt -d wheels

# ② 승인된 방법으로 wheels 폴더 반입 후, 사내 PC
python -m pip install --no-index --find-links wheels -r requirements.txt

반입은 반드시 회사 보안 절차대로. 출처 모를 wheel은 설치 자체가 실행입니다.

주소 "pypi.사내미러"는 자리 표시입니다. 실제 주소와 허용 여부는 인프라·보안 담당과 확인하세요. B 방법은 받는 PC와 설치할 PC의 운영체제와 파이썬 버전이 같아야 합니다. 바퀴 파일이 OS · 버전별로 다르게 만들어지기 때문입니다.

# CLAUDE.md — 환경
- 가상환경: .venv  (실행: .venv\Scripts\python.exe)
- 패키지 설치 전 먼저 물어볼 것. 설치하면
  requirements.txt에 == 버전으로 추가
- 명령은 Windows PowerShell 기준
- 파이썬 3.11 (서버와 같게)

한 개로 될 걸 네 개 깔지 않게

"표준 라이브러리나 이미 있는 패키지로 되면 그걸로"를 덧붙이면 의존성이 줄어듭니다.

에이전트는 문제를 빨리 풀려고 패키지를 많이 설치하는 경향이 있습니다. 규칙 네 줄이면 대부분 막힙니다. 패키지가 늘수록 보안 점검 대상도 늘어납니다.

🖐 실습 · 지우고 다시 만들어도 돈다 (20분)

내 프로젝트를 상자 + 목록으로

배우는 것 — venv를 만들고, 버전을 고정하고, 상자를 지워도 목록만으로 되살리는 법.

⌨️ 순서대로
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt   # 없으면 AI에게 만들게
python 내스크립트.py                         # 돌아가는지
python -m pip freeze > requirements.txt
deactivate
Remove-Item -Recurse .venv                  # 상자 버리기!
# 처음 세 줄 다시 → 내스크립트 다시 실행

✅ 완료 기준

  • 상자를 지웠다 다시 만들어도 스크립트가 그대로 돈다
  • sys.executable에 .venv가 보인다
  • requirements.txt의 모든 줄에 ==가 있다
