CASE 1 · KeyError — 보이지 않는 공백

"분명히 '두께' 열이 있는데요?" — 눈에 안 보이는 한 칸

>>> df["두께"]
KeyError: '두께'
>>> print(list(df.columns))
['날짜', '설비', '두께 ', '균일도']
            ↑ 끝에 공백 한 칸
# 처방: 열 이름 앞뒤 공백을 지우고 시작
df.columns = df.columns.str.strip()

왜 생기나

엑셀에서 머리글을 고치다 공백이 들어가거나, 시스템마다 내보내는 형식이 조금씩 다릅니다.

확인 한 줄

KeyError가 나면 list(df.columns)로 진짜 이름을 출력합니다. 따옴표 안까지 봅니다.

다시는 안 나게

"CSV를 읽으면 열 이름부터 strip" — CLAUDE.md에 한 줄. 하네스 덱의 래칫입니다.

클릭하면 확인 → 처방 순서로 나옵니다. 사람 눈에는 '두께'와 '두께 '가 같아 보이지만 컴퓨터에는 다른 글자입니다. 비슷한 함정: 전각 괄호, 줄바꿈이 들어간 머리글, 'Thickness'와 'thickness'.
CASE 2 · UnicodeDecodeError — 한글 CSV

엑셀에서 저장한 한글 CSV는 utf-8이 아닐 때가 많습니다

>>> pd.read_csv("측정결과.csv")
UnicodeDecodeError: 'utf-8' codec can't decode
byte 0xb3 in position 0: invalid start byte

읽는 법

'utf-8'로 읽으려 했는데, 첫 글자(position 0)부터 utf-8 규칙에 맞지 않는다 → 파일이 다른 방식으로 저장됐다.

# 엑셀 "CSV(쉼표로 분리)"는 대개 cp949
df = pd.read_csv("측정결과.csv", encoding="cp949")

# 저장할 때 엑셀에서 한글이 안 깨지게
df.to_csv("out.csv", encoding="utf-8-sig", index=False)

인코딩 = 글자를 숫자로 적는 방식

같은 '가'도 utf-8과 cp949는 다른 숫자로 적습니다. 방식이 다르면 읽다가 멈춥니다.

반대 증상: 깨진 글자

에러 없이 ì¸¡ì •처럼 나오면, 읽는 방식이 틀렸는데 우연히 멈추지 않은 경우입니다.

utf-8-sig

파일 앞에 표식(BOM)을 붙여, 엑셀이 utf-8 파일임을 알아보게 합니다.

한국 사내 환경에서 가장 흔한 에러 중 하나입니다. 엑셀의 기본 CSV 저장은 대개 cp949(EUC-KR 계열)입니다. 엑셀 버전과 저장 옵션에 따라 "CSV UTF-8"을 고를 수도 있습니다. 바이트 값(0xb3 등)은 파일마다 다릅니다. 핵심은 'utf-8' codec can't decode라는 문구입니다.
CASE 3 · AttributeError: 'NoneType' — 범인은 위에

에러가 난 줄이 꼭 원인은 아닙니다

def load_week(week):
    path = find_file(week)
    if path is None:
        print("파일 없음")
        return                # ← 여기서 아무것도 안 돌려줌 (None)
    return pd.read_csv(path)

df = load_week(48)
summary = df.groupby("설비").mean()   # ← 에러는 여기서
AttributeError: 'NoneType' object has no attribute 'groupby'

읽는 법

"None이라는 물건에는 groupby 기능이 없다" → df가 데이터가 아니라 비어 있다(None).

그럼 왜 비었나?

df를 만든 곳으로 거슬러 올라갑니다. 48주차 파일이 없어서 return만 하고 끝났습니다.

처방

못 찾으면 조용히 None을 돌려주지 말고 바로 에러를 내게: raise FileNotFoundError(week)

"에러는 증상이 드러난 곳에서 나고, 원인은 더 위에 있다"는 가장 중요한 감각입니다. NoneType이 보이면 무조건 "이 변수를 만든 곳"을 찾아 올라갑니다. 처방이 흥미롭습니다: 에러를 없애는 게 아니라, 원인이 있는 곳에서 더 일찍, 더 분명하게 나게 만듭니다.

🖥️ 서버 터미널

백엔드(파이썬)의 Traceback은 서버를 띄운 터미널에 찍힙니다. 브라우저에는 "500"만 보입니다.

🧰 F12 → Console

프론트(자바스크립트) 에러. TypeError: Cannot read properties of undefined가 단골입니다.

🌐 F12 → Network

요청마다 상태 코드. 4xx는 요청한 쪽, 5xx는 서버 쪽부터 봅니다.

보이는 것뜻어디서 진짜 이유를 보나
404 Not Found그런 주소가 없다프론트의 요청 주소 vs 백엔드의 주소 정의
500 Internal Server Error서버 코드에서 사고서버 터미널의 Traceback — 이 덱의 읽는 법 그대로
CORS policy다른 주소에서 온 요청을 서버가 막음백엔드의 허용 주소 설정
웹 앱에서 가장 흔한 실수는 브라우저 화면의 "500"만 AI에게 보여 주는 것입니다. 진짜 이유는 서버 터미널에 있습니다 — 그걸 함께 붙여야 합니다. 층 구분은 "프로그램의 구조 한 장" 덱과 연결됩니다.

연습용 폴더에 파이썬 파일을 만들어줘.
실행하면 KeyError, UnicodeDecodeError,
'NoneType' AttributeError가 하나씩 차례로 나게.

✅ 완료 기준

  • 세 에러 모두 에러 이름과 이유를 말했다
  • 세 에러 모두 내 파일의 줄 번호를 찾았다
  • NoneType은 원인이 된 위쪽 줄까지 찾았다
