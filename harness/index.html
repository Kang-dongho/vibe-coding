차이는 모델이 아니라 모델이 일하는 환경에 있습니다.

클릭할 때마다 양쪽이 한 줄씩 동시에 진행됩니다. 숫자는 설명을 위한 예시입니다. "본인 얘기 같은 분?" A와 B는 같은 도구, 같은 모델을 씁니다. B는 프롬프트를 더 잘 쓰는 게 아니라, 실수가 나올 때마다 환경에 한 줄씩 쌓아 온 사람입니다. 그 환경을 오늘은 "하네스"라고 부릅니다.
DEFINITION · 하네스란

말에게 씌우는 마구(harness)처럼 — 힘을 일로 바꾸는 장치

하네스AI가 일하는 환경 전체
도구권한검사·훅기록분업
컨텍스트지금 AI의 책상 위 — 규칙 파일 · 열어 본 파일 · 대화
프롬프트이번 한 번의 지시 — "이번 주 데이터만 봐줘"

안쪽일수록 한 번, 바깥일수록 매번

프롬프트는 이번 요청에만, 하네스는 모든 요청에 작동합니다.

Claude Code도 하네스입니다

도구 회사가 만든 기본 하네스 위에 우리가 규칙·권한·검사를 얹어 내 하네스로 만듭니다.

모델이 아닌 모든 것이 하네스입니다. 그래서 내가 손댈 수 있는 거의 전부가 여기에 있습니다.

harness는 원래 말이나 썰매견에게 씌우는 마구입니다. 힘(모델)은 그대로인데, 마구가 그 힘을 어디로 쓸지 정합니다. 층으로 보면: 프롬프트 ⊂ 컨텍스트 ⊂ 하네스. 컨텍스트 덱에서 "'System' 칸은 하네스가 채웁니다"라고 했던 그 하네스입니다. Claude Code, Codex 같은 코딩 도구는 도구 회사가 만든 기본 하네스이고, 우리는 그 위에 규칙·권한·검사를 얹어 내 하네스로 만듭니다.

AI가 헤매면 "모델이 멍청하다"가 아니라 "어느 칸이 비었나"를 묻습니다.

이 덱의 중심 그림입니다. 칸 이름은 이 덱에서 쓰는 분류이고, 업계에 정해진 표준 목록은 없습니다 — 다른 글에서는 메모리, 피드백 루프 같은 이름도 씁니다. 한 칸씩 짚으며 "지금 내 환경에서 이 칸은 어떤가?"를 묻습니다. 다음 장부터 칸마다 한 장씩 봅니다.
THE LOOP · 하네스가 끼어드는 자리

에이전트는 이 루프를 수십 번 반복합니다

칸마다 끼어드는 자리가 있습니다. 노란 관문은 모델이 잊어도 하네스가 반드시 거치게 합니다.

점이 루프를 도는 동안 한 칸씩 짚습니다. 모델은 매 턴 컨텍스트 전체를 다시 읽고(①), 쓸 수 있는 도구 중에서 고르고(②), 실행 전에 권한 검사를 지나고(③), 실행 뒤에는 훅이 돌고(④), 그 결과가 다시 컨텍스트로 들어갑니다. 핵심 메시지: ③과 ④는 모델의 "기억"에 기대지 않습니다. 모델이 깜빡해도 하네스가 반드시 그 관문을 지나게 합니다. 그래서 꼭 지켜야 하는 것은 규칙 파일보다 권한·훅에 둡니다.

  • python scripts/merge_csv.pyallow · 바로 실행
  • git push origin mainask · 나에게 물어봄
  • Edit data/raw/w47.csvdeny · 차단

allow · ask · deny 세 칸

자주 쓰는 안전한 명령은 허용하고, 되돌리기 어려운 건 물어보게 하고, 절대 안 되는 건 막습니다. 원본 데이터는 읽기만, 결과는 out/에만 씁니다.

사람 없이 돌릴수록 좁게

예약 실행·자동화에서는 ask에 답할 사람이 없습니다. 허용 목록을 더 줄입니다.

Claude Code 기준 예시입니다. 다른 도구에도 비슷한 허용/거부 설정이 있습니다. 문법은 공식 문서와 setup 덱을 확인하세요. 말로 "원본은 건드리지 마"라고 하는 것과 deny 규칙으로 막는 것은 다릅니다 — 말은 잊히고, 설정은 남습니다. 권한 설계 원칙의 정본은 security 덱입니다.

④ 검증

AI가 스스로 틀린 걸 알 수 있는 신호를 줍니다

완료 기준을 숫자로

"리포트 만들어줘" → "행 수가 원본과 같고(12,431), 설비별 평균이 소수 1자리면 완료".

검사는 AI가 직접 돌리게

검사 스크립트를 주고 "통과할 때까지 고쳐"라고 하면, 사람이 보기 전에 고치는 과정이 한 바퀴 돌아갑니다.

훅 — 파일을 고칠 때마다 자동 검사 (예시)

{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
                  "command": "python scripts/check_report.py" }]
    }]
  }
}

훅은 AI가 잊어도 매번 실행됩니다.

검증은 여섯 칸 중 효과가 가장 큰 칸입니다. 모델은 피드백이 있으면 스스로 고칩니다 — 피드백이 없으면 "다 됐어요"라고 합니다. 규칙 파일은 "하라고 말하는 것", 훅은 "하게 만드는 것"입니다. 꼭 지켜야 하는 검사는 훅으로. 훅 문법은 도구와 버전에 따라 다르니 공식 문서를 확인. 검증 전략 전체는 verification 덱이 정본입니다.

④ 검증 · 예시

검증 루프 한 바퀴 — 사람이 보기 전에 이미 고쳐져 있습니다

scripts/check_report.py — 숫자 대조 (예시)

import glob, sys
import pandas as pd

raw = pd.concat(pd.read_csv(f, skiprows=3)
                for f in glob.glob("data/raw/*.csv"))
rep = pd.read_csv("out/report.csv")

n_rep = rep["count"].sum()
if n_rep == len(raw):
    print("PASS"); sys.exit(0)
print(f"FAIL 행 수 {n_rep:,} ≠ 원본 {len(raw):,}")
sys.exit(1)   # 실패 → AI가 메시지를 읽고 다시 고침

만든 사람이 검사하면, 자기 답에 후합니다

🔍 탐색 담당

파일 수백 개를 뒤지는 일은 따로 시키고 결론만 받습니다. 내 책상이 깨끗하게 유지됩니다.

🛠️ 작성 담당

코드·리포트를 만듭니다. 완료 기준을 받고 시작합니다.

⚖️ 검토 담당

만든 과정을 모르는 상태로 결과만 봅니다. "통과·실패 + 이유"로 답하게 합니다.

처음부터 팀을 짤 필요는 없습니다. 검토만 따로 떼어 내는 것이 가장 싸고 효과가 큽니다.

서브에이전트는 자기만의 컨텍스트에서 일하고 결과만 돌려줍니다. 장점 두 가지: 내 컨텍스트가 덜 차고, 검토가 독립적입니다. 비용은 늘어납니다. 그래서 "검토만 분리"가 가장 가성비가 좋습니다. 패턴 전체는 orchestration 덱이 정본입니다.

실수 하나가 한 칸에 한 줄로 쌓이면, 되돌아가지 않습니다

① 실수 발견"헤더 3줄을 또 데이터로 읽었네"
→
② 칸 고르기설명이 없었나(컨텍스트)? 확인을 못 했나(검증)? 해선 안 될 일을 할 수 있었나(권한)?
→
③ 한 줄 남기기규칙 한 줄 · 검사 한 개 · deny 한 줄 — 가장 강한 것으로
→
④ 일부러 다시 시켜 보기같은 실수를 유도해서, 이번엔 막히는지 눈으로 확인
강도방법언제
약함CLAUDE.md에 규칙 한 줄판단이 필요한 습관 — "이상치는 지우지 말고 표시"
중간검사 스크립트 + 완료 기준숫자로 맞고 틀림이 갈리는 것 — 합계, 행 수
강함deny 권한 · 훅한 번이라도 일어나면 안 되는 것 — 원본 덮어쓰기, 키 노출
래칫은 한쪽으로만 도는 톱니입니다. 실수를 고칠 때마다 하네스에 한 줄을 쌓으면, 같은 실수로는 되돌아가지 않습니다. "가장 강한 것으로": 규칙은 무시될 수 있고, 검사는 잡아내고, 권한은 아예 못 하게 합니다. 중요도에 맞춰 고릅니다. ④가 핵심입니다. 설정만 하고 확인하지 않으면, 오타 하나 때문에 실제로는 막혀 있지 않은 경우가 많습니다.

오른쪽 꼬리표가 래칫의 강도입니다. 말로만 남긴 줄보다 권한·훅으로 받친 줄이 오래 갑니다.

왼쪽은 실제로 흔히 쓰는 지시입니다. 모두 "알겠습니다"라는 답은 받지만, 지켰는지 판정할 수 없습니다. 오른쪽은 다른 사람이 결과를 보고 지켰는지 예/아니오로 답할 수 있습니다. 클릭할 때마다 하나씩 바뀝니다. 청중에게 자기 CLAUDE.md에서 왼쪽 같은 줄을 하나 찾아 오른쪽처럼 바꿔 보게 하면 좋습니다.
DIAGNOSIS · 증상 → 빈 칸 → 처방

AI가 이럴 때, 프롬프트 말고 하네스를 고칩니다

증상빈 칸처방 한 줄
같은 설명을 매번 다시 한다① 컨텍스트두 번 한 지적은 CLAUDE.md에 숫자·금지로
파일을 안 열어 보고 추측한다② 도구읽기 전용 조회 도구·스크립트를 주고 "확인 후 답해"
안 시킨 파일까지 고쳤다③ 권한쓰기 가능한 폴더를 한 곳으로, 원본은 deny
"다 됐어요"인데 틀려 있다④ 검증완료 기준을 숫자로 + 검사 스크립트를 직접 돌리게
긴 작업 중 앞 결정을 뒤집는다⑤ 상태PROGRESS.md에 결정을 적고, 새 세션은 그 파일부터
만들고 스스로 "완벽합니다"⑥ 분업과정을 모르는 검토 담당에게 결과만 보여주기
이 표가 이 덱의 처방전입니다. 청중에게 최근 겪은 증상을 하나 고르게 하고, 어느 칸인지 같이 맞혀 봅니다. 한 증상에 여러 칸이 걸릴 수 있습니다. 그럴 땐 래칫 표의 "강도"가 높은 쪽부터.
EXAMPLE · 주간 공정 리포트 에이전트의 하네스

폴더 하나에 여섯 칸이 다 들어갑니다

weekly-report/
├─ CLAUDE.md            # ① 헤더 3줄·단위·제외 설비
├─ scripts/
│  ├─ merge_csv.py      # ② 도구 — 이름·인자 한 줄 설명
│  └─ check_report.py   # ④ 합계·행 수 대조
├─ .claude/
│  ├─ settings.json     # ③ raw/ deny · ④ 훅
│  └─ agents/reviewer.md # ⑥ 검토 담당
├─ data/raw/            # 읽기 전용
├─ out/                 # 쓰기는 여기만
└─ PROGRESS.md          # ⑤ 진행·결정 기록

"이번 주 리포트 만들어줘" 한 줄이 들어오면

  • ① CLAUDE.md를 읽고 헤더·단위·제외 설비를 압니다컨텍스트
  • ② merge_csv.py로 12개 파일을 합칩니다도구
  • ③ 실수로 raw/ 파일을 고치려다 막힙니다권한
  • ④ 훅이 숫자를 대조하고, FAIL이면 다시 고칩니다검증
  • ⑤ reviewer가 과정을 모른 채 결과만 검토합니다분업
  • ⑥ PROGRESS.md에 결과와 결정을 남깁니다상태

사람은 마지막 검수만 합니다. 최종 판단과 책임은 사람에게 있습니다.

구조 예시입니다. 실제 파일명·설비명은 각자 업무에 맞게 바꿉니다. 실데이터는 사내 승인 도구에서만(보안 약속 1). 포인트: 하네스는 거창한 플랫폼이 아니라 폴더 하나에 들어가는 파일 몇 개입니다. 처음부터 다 만들 필요 없이, 실수가 나올 때마다 한 칸씩 채웁니다.

파일 하나 고칠 때마다 5분짜리 검사가 돌면 아무도 안 씁니다. 빠른 검사만 훅으로.

한 달에 한 번, "이 줄이 아직 실수를 막고 있나?"를 묻고 정리합니다.

래칫의 부작용입니다. 규칙과 도구는 쌓이기만 하고 지워지지 않는 경향이 있습니다. 모델이 좋아지면 예전엔 필요했던 규칙이 필요 없어지기도 합니다. 정기적으로 걷어냅니다.

정리

오늘 가져갈 습관 세 가지

1. 탓하기 전에 칸을 본다

모델 탓 대신 컨텍스트 · 도구 · 권한 · 검증 · 상태 · 분업 중 빈 칸을 찾습니다.

2. 실수는 한 줄로 고정한다

말로 혼내지 말고, 가장 강한 방법으로 하네스에 남기고, 막히는지 확인합니다.

3. 쌓은 만큼 걷어낸다

더 이상 실수를 막지 않는 줄은 지웁니다. 가벼운 하네스가 오래 갑니다.

세 습관으로 마무리. 다음 단계로 각 칸의 정본 덱(context · agent-skills · security · verification · orchestration)을 안내하고 Q&A.
