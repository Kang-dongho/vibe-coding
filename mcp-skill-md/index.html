  1. 1

  3. 3
    MCP = 바깥 시스템에 꽂는 표준 플러그DB · 브라우저 · 위키를 AI의 도구로. 내 권한으로 돌아가니 출처와 권한을 먼저 봅니다.

HOW · AI의 작업 상자에 언제 들어가나

.MD는 처음부터, Skill은 펼칠 때, MCP 결과는 부를 때

.MD는 짧게

매 세션 자리를 차지합니다. 공식 권장은 파일당 200줄 이하.

Skill은 길어도 된다

안 쓰는 날엔 한 줄 값만 냅니다. 대신 설명 한 줄이 잘 써져야 펼쳐집니다.

MCP는 결과가 크다

표 1만 행을 통째로 받으면 상자가 찹니다. "요약해서 가져와"가 기본.

막대가 AI의 작업 상자(컨텍스트)입니다. 클릭할 때마다 스킬 본문, 그다음 MCP 결과가 들어오며 막대가 늘어납니다. 칸 크기는 설명용 예시입니다. Claude Code는 MCP 도구가 많을 때 도구 설명도 필요할 때 찾아 불러오는 기능(tool search)이 기본으로 켜져 있습니다. 그래도 안 쓰는 서버는 빼 두는 게 좋습니다.

① .MD · 어디에 두나

개인 · 팀 · 폴더, 세 층으로 쌓아 읽습니다

합쳐서 읽힌다

위의 파일이 아래 파일을 덮어쓰지 않습니다. 전부 이어 붙여서 읽고, 작업 폴더에 가까운 것이 마지막에 옵니다.

AGENTS.md와 함께 쓰기

여러 AI 도구가 같이 읽는 공용 파일이 AGENTS.md. Claude Code는 CLAUDE.md를 읽으니, 첫 줄에 @AGENTS.md로 불러옵니다.

처음엔 /init

코드를 훑어 초안을 써 줍니다. 그다음은 AI가 틀릴 때마다 한 줄씩.

클릭할 때마다 파일 하나씩. 개인 · 팀 · 폴더 세 층만 기억하면 됩니다. frontend/CLAUDE.md처럼 하위 폴더의 파일은 처음부터 읽히지 않고, AI가 그 폴더의 파일을 열 때 함께 읽힙니다. /memory 명령으로 지금 어떤 파일들이 읽혔는지 확인할 수 있습니다.

② SKILL · 폴더 하나 = 절차서 하나

핵심은 본문이 아니라 description 한 줄입니다

├─ checklist.md      필요할 때 더 읽음
├─ template.pptx     양식

   └─ build.py       실행만 함 (안 읽음)

두 군데에 둘 수 있다

.claude/skills/ = 이 프로젝트(팀과 git 공유) · ~/.claude/skills/ = 내 모든 프로젝트.

---
name: weekly-report
description: CMP 주간 두께 리포트(PPT)를 만든다. "주간보고",
  "주간 리포트", "W47 보고서"처럼 주간 정리를 요청할 때 사용.

## 절차
1. data/raw/ 의 이번 주 CSV를 읽는다 (헤더 3줄, EQ-01 제외)
2. python scripts/build.py --week W47 실행
3. 검산: 행 수 = 원본 합계, 평균 한 줄 손계산 → 로그로 남김
4. 지난주 파일은 backup/ 으로 옮긴 뒤 저장
## 막히면
- DRM 엑셀이면 checklist.md 의 "xlwings" 절 참고
AI는 세션 시작 때 모든 스킬의 이름과 description만 봅니다. 사용자의 요청이 description과 맞으면 그때 본문을 펼칩니다. 그래서 description에는 "무엇을 하는지"와 "언제 쓰는지(사용자가 실제로 할 법한 말)"를 함께 적습니다. 노란 줄이 그 부분입니다. /weekly-report처럼 슬래시로 직접 부를 수도 있습니다. 배포처럼 되돌리기 어려운 스킬은 disable-model-invocation: true로 AI가 스스로 부르지 못하게 합니다.

서버 = 작은 프로그램

"이런 도구가 있어요"라는 목록을 AI에게 알려 주고, 불리면 실행해서 결과를 돌려줍니다.

표준이라 재사용

한 번 만든 서버를 Claude Code · 다른 AI 도구에서 그대로 씁니다. 도구마다 연결을 새로 짜지 않습니다.

대부분은 도구(Tools)

서버는 읽을 거리(Resources)와 프롬프트 양식(Prompts)도 줄 수 있지만, 실무에선 도구가 거의 전부입니다.

노란 점이 AI의 요청과 결과입니다. AI는 DB 접속법을 몰라도 "query"라는 도구가 있다는 것만 알면 됩니다. USB-C 비유: 예전엔 기기마다 충전기가 달랐습니다(도구마다 따로 만든 연동). MCP는 플러그 모양을 하나로 맞춘 표준입니다.
③ MCP · 한 번 부르면 생기는 일

AI는 도구 이름과 인자만 정하고, 실행은 서버가 합니다

"어제 EQ-03 평균 두께 알려줘"

나어제 EQ-03 평균 두께 알려줘

🧠 쓸 도구 고르기 → cmp-db.query

🔐 권한 확인: "cmp-db의 query를 실행할까요?" → 허용

→ query({"sql": "SELECT AVG(avg_thk) FROM thk WHERE eq='EQ-03' AND day='11-23'"})

← [{"avg": 4005.5}]

AI어제(11-23) EQ-03 평균 두께는 4005.5 Å입니다. 측정 2건 기준

사람이 붙여 넣던 일

"DB 열고 → 쿼리 → 결과 복사 → 붙여 넣기"가 사라집니다.

허락은 처음 한 번

도구를 처음 쓸 때 물어봅니다. 읽기 도구는 허용 목록에, 쓰기 도구는 매번 확인으로.

결과도 의심

SQL 덱의 함정(NULL · JOIN 중복)은 MCP로 가져와도 그대로입니다. 건수 검산은 계속.

도구 이름, 쿼리, 결과는 설명용 예시입니다. 실제 사내 DB용 MCP 서버는 인프라 · 보안 담당과 함께 정해야 합니다. 핵심은 AI가 데이터를 "기억"하는 게 아니라 매번 "가져온다"는 점입니다. 그래서 최신 값입니다.

③ MCP · 연결하는 법

명령 한 줄로 꽂고, .mcp.json으로 팀과 나눕니다

# 내 PC에서 실행되는 서버 (stdio)
claude mcp add playwright -- npx @playwright/mcp@latest

# 원격 서버 (http)
claude mcp add --transport http wiki https://mcp.intranet.example/wiki

# 팀 공유: 프로젝트 범위 → .mcp.json 생성
claude mcp add --scope project playwright -- npx @playwright/mcp@latest

# 확인
claude mcp list          playwright ✔ Connected
# 세션 안에서  /mcp
// .mcp.json — git에 올려 팀이 같이 씀
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

MCP 서버는 내 권한으로 도는 프로그램입니다

  • 1출처 — 공식 · 사내 승인 서버만. 모르는 저장소의 서버는 설치 자체가 실행입니다가장 먼저
  • 2계정 — DB는 읽기 전용 계정으로 연결. 쓰기 도구는 매번 확인권한
  • 3되돌아오는 글 — 위키 · 이슈 · 웹페이지 속 "이전 지시를 무시하고…"는 데이터일 뿐주입 공격
  • 4비밀 — 토큰은 ${API_KEY}처럼 환경변수로. .mcp.json에 직접 쓰지 않기git 주의
  • 5개수 — 안 쓰는 서버는 끄기. 도구가 많을수록 AI가 고르기 어려워집니다정리

사내망에서는 npx 다운로드가 막힐 수 있습니다. 서버 설치는 사내 배포 절차를 따르세요.

클릭할 때마다 하나씩. 1번이 가장 중요합니다. MCP 서버는 그냥 프로그램이라, 악성 서버를 설치하면 내 PC 권한으로 무엇이든 할 수 있습니다. 3번(프롬프트 인젝션)은 보안 덱에서 자세히 다룹니다. MCP로 가져온 글에 숨은 지시가 있을 수 있습니다.
