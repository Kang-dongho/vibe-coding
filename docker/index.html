그래서 리눅스 컨테이너는 리눅스 커널이 필요합니다. Windows에서는 WSL2(작은 리눅스)가 그 역할을 합니다. 대신 격리는 VM보다 얇습니다 — 샌드박스 장에서 다시.

VM은 OS를 통째로 하나 더 띄웁니다. 컨테이너는 같은 커널 위에서 칸막이만 칩니다. 그래서 가볍고 빠릅니다. 마지막 줄이 중요한 복선입니다: 커널을 같이 쓰기 때문에, 보안 경계로서는 VM이 더 두껍습니다.
① CONTAINER · 칸막이 네 개

컨테이너 안에서 보면, 세상에 나 혼자입니다

📁 파일자기만의 /. 내 PC의 C:\ 는 안 보임 (붙여 주기 전엔)
⚙️ 프로세스자기 프로그램만 보임. 내 앱이 PID 1
🌐 네트워크자기 주소 · 포트. 밖과 잇는 건 내가 정함
📊 자원CPU · 메모리 상한을 걸 수 있음
PS> docker exec -it dash sh      # 상자 안으로 들어가기
/app $ ps

  1   app    python -m streamlit run app.py

/app $ ls /
app  bin  etc  home  lib  proc  tmp  usr  var

3f2a9c1e7b04

리눅스의 namespace(보이는 범위 나누기)와 cgroup(자원 한도)이라는 기능으로 만듭니다. 이름만 알아 두면 됩니다.

출력은 예시입니다. 상자 안에서 ps를 치면 내 PC의 수백 개 프로그램은 안 보이고 앱 하나만 보입니다. hostname도 상자 고유 이름입니다. 이 네 칸막이가 뒤의 샌드박스 장에서 그대로 "막을 것 네 가지"가 됩니다.
② DOCKERFILE · 레시피 한 줄씩

위에서 아래로 층을 쌓습니다 — 자주 바뀌는 건 맨 위에

FROM python:3.11-slim                 # ① 바탕: 파이썬 깔린 작은 리눅스
WORKDIR /app                          # ② 상자 안 작업 폴더
COPY requirements.txt .               # ③ 목록 먼저
RUN pip install --no-cache-dir -r requirements.txt  # ④ 설치 (오래 걸림)
COPY . .                              # ⑤ 내 코드 (자주 바뀜)
RUN useradd -m app
USER app                              # ⑥ root 아닌 사용자로
EXPOSE 8501
CMD ["python", "-m", "streamlit", "run", "app.py",
     "--server.address=0.0.0.0"]     # ⑦ 켜질 때 실행할 것
🐍 바탕 — python:3.11-slimFROM
📋 requirements.txtCOPY
📦 패키지 설치RUN
✏️ 내 코드COPY . .

.dockerignore도 같이

.venv · .env · data/ · .git을 적어 두면 상자에 안 들어갑니다. 비밀이 이미지에 박히는 사고를 막습니다.

층 순서의 이유는 K8S 덱의 이미지 층 장과 같습니다. 코드만 고치면 ⑤ 층만 다시 굽습니다. 0.0.0.0은 "상자 밖에서 오는 요청도 받아라"라는 뜻입니다. 이걸 빼면 상자 안에서만 접속되는 함정에 빠집니다. Windows에서 만든 스크립트를 COPY해 실행한다면 줄바꿈을 LF로 — 파일 형식 덱.
SEE K8S — 이미지 층 파일 형식 — 줄바꿈

옵션뜻
-d뒤에서 실행 (창을 안 붙잡음)
--name dash부를 이름
-p 내PC:상자문 잇기. -p 9000:8501이면 localhost:9000
노란 점이 브라우저 요청이 내 PC의 8501번 문을 지나 상자의 8501번 문으로 들어가는 모습입니다. -p를 빼면 상자는 잘 돌고 있는데 브라우저에선 접속이 안 됩니다. 컨테이너 입문 첫날 가장 흔한 질문입니다.

규칙 하나

코드 · 환경 = 이미지, 데이터 = 볼륨, 설정 · 비밀 = 환경변수. 이 셋을 섞지 않으면 상자는 언제 버려도 됩니다.

애니메이션: 상자가 지워지면 안의 파일은 같이 사라지고, 볼륨에 쓴 파일은 남습니다. "상자는 일회용"은 단점이 아니라 장점입니다. 망가지면 지우고 새로 띄우면 됩니다 — 이게 뒤에서 샌드박스의 핵심이 됩니다. 환경변수는 터미널 덱의 "쪽지"와 같은 개념입니다.

④ COMPOSE · 상자 여러 개를 한 장으로

앱 + DB를 파일 하나로 함께 띄웁니다

# compose.yaml
services:
  app:
    build: .
    ports: ["8501:8501"]
    env_file: .env
    environment:
      DB_URL: "postgresql://cmp@db:5432/cmp"   # ← 이름 db로 찾음
    depends_on: [db]
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: cmp
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes: ["pgdata:/var/lib/postgresql/data"]
volumes:
  pgdata:
PS> docker compose up -d     # 둘 다 켜기
PS> docker compose logs -f app
PS> docker compose down      # 둘 다 끄기 (볼륨은 남음)

서로를 이름으로 부른다

앱은 DB 주소를 db라는 이름으로 찾습니다. IP를 몰라도 됩니다.

YAML이다

들여쓰기 · 따옴표 함정은 파일 형식 덱 그대로. 포트는 따옴표로 감싸는 게 안전합니다.

K8S의 예고편

"상자 여러 개를 선언으로 관리"를 서버 여러 대로 키운 것이 K8S입니다.

compose 파일 하나가 "이 앱을 돌리려면 무엇이 필요한가"의 문서이기도 합니다. 새로 온 사람도 docker compose up 한 줄로 시작합니다. 비밀번호는 ${DB_PASSWORD}처럼 .env에서 읽습니다. 파일에 직접 쓰지 않습니다.
KIT · 자주 쓰는 명령

이 열 개면 일상 업무는 됩니다

명령뜻비고
docker build -t 이름:태그 .이미지 굽기태그는 버전 — latest만 쓰지 않기
docker run -d -p … --name …컨테이너 띄우기
docker ps · docker ps -a실행 중 · 꺼진 것까지
docker logs -f 이름로그 따라 보기안 될 때 첫 번째
docker exec -it 이름 sh상자 안으로 들어가기구경만, 고치지는 않기
docker stop · docker rm끄기 · 지우기
docker images가진 이미지
docker compose up -d · down여러 개 한 번에
docker system prune -a --volumes안 쓰는 것 몽땅 삭제볼륨 데이터까지 — 확인 필수

상자 안에서 고친 건 지우면 사라집니다. 고칠 건 Dockerfile을 고치고 다시 굽기.

exec로 들어가서 설정을 고치는 건 임시방편입니다. 다음에 새로 띄우면 원래대로 돌아갑니다. 영구 수정은 레시피(Dockerfile)에서. prune에 --volumes가 붙으면 DB 데이터가 날아갈 수 있습니다. AI가 이 명령을 제안하면 멈추세요.
⑤ SANDBOX · 모래상자

샌드박스 = 안에서 무엇을 해도 밖은 안전한 상자

🏖️ 놀이터 모래상자

아이가 안에서 성을 부수고 파헤쳐도 놀이터 바닥은 멀쩡합니다. 끝나면 모래를 고르면 원래대로.

🧪 팹의 테스트 웨이퍼

새 레시피는 제품 웨이퍼가 아니라 테스트 웨이퍼로 먼저. 망가져도 손해가 상자 안에서 끝납니다.

샌드박스를 만드는 방법격리 두께
🌐 브라우저 탭 — 웹페이지가 내 파일을 못 봄얇음 · 늘 쓰는 중
🔒 OS 샌드박스 — 명령 하나하나를 OS가 제한얇음 · 가벼움
📦 컨테이너 — 파일 · 프로세스 · 네트워크 · 자원중간 · 오늘의 주인공
🖥️ 가상 머신 — OS를 통째로두꺼움 · 무거움

컨테이너는 도구, 샌드박스는 목적. 컨테이너를 쓴다고 저절로 샌드박스가 되진 않습니다 — 문을 잠가야 합니다.

샌드박스는 기술 이름이 아니라 쓰임새의 이름입니다. 컨테이너, VM, 브라우저 탭 모두 샌드박스로 쓰일 수 있습니다. 마지막 줄이 핵심입니다. -v로 C:\ 전체를 붙이고 네트워크를 열어 두면, 그 컨테이너는 샌드박스가 아닙니다.

명령마다 허락을 구하면 결국 안 읽고 "예"를 누르게 됩니다. 상자가 대신 막아 주면 정말 중요한 것만 묻습니다.

프롬프트 인젝션

읽은 문서 속 "이 파일을 외부로 보내라"에 속아도, 나갈 길이 없으면 피해가 없습니다.

되돌리기 = 버리기

엉망이 되면 상자를 버리고 새로. git과 함께면 코드도 안전합니다.

아래 세 개의 시도가 차례로 켜지며 상자 벽(🧱)에 막힙니다. rm -rf는 상자 안에서만 일어나고, 외부 통신과 비밀 파일은 애초에 길이 없습니다. 하네스 덱의 권한(③)이 "말로 막기"라면, 샌드박스는 "벽으로 막기"입니다. 둘을 같이 씁니다.

⑤ SANDBOX · 문 다섯 개를 잠그기

컨테이너를 샌드박스로 만드는 옵션들

docker run --rm -it \
  --network none \
  -v "${PWD}:/work" -w /work \
  --user 1000:1000 \
  --memory 2g --cpus 2 --pids-limit 256 \
  --cap-drop ALL --security-opt no-new-privileges \
  python:3.11-slim bash
잠글 문옵션막는 것
🌐 네트워크--network none (또는 허용 목록 프록시)밖으로 보내기 · 이상한 것 내려받기
📁 파일프로젝트 폴더만 -v, 읽기만이면 :ro다른 폴더 · ~/.ssh · 회사 문서
👤 권한--user · --cap-drop ALL · no-new-privilegesroot로 상자 벽 긁기
📊 자원--memory · --cpus · --pids-limit무한 루프로 PC 멈추기
🔑 비밀토큰 · .env를 넣지 않기상자 안에 있으면 언젠가 샘
--rm은 끝나면 상자를 자동으로 지웁니다. 일회용 실험실의 기본값. 네트워크를 완전히 끊으면 pip install도 안 됩니다. 실무에선 필요한 주소만 허용하는 프록시나 방화벽을 둡니다(다음 장의 dev container 예). 완벽한 벽은 없습니다. 커널을 같이 쓰므로, 정말 위험한 코드는 VM 수준의 격리가 필요합니다.
⑤ SANDBOX · Claude Code에서는

두 가지 방법 — 명령만 가두기 vs 통째로 상자에

🔒 /sandbox — 내장 샌드박스

  • Claude가 치는 셸 명령을 OS가 제한 (macOS · Linux · WSL2)
  • 쓰기는 작업 폴더 중심, 네트워크는 허용한 도메인만
  • 그 안의 명령은 매번 묻지 않고 실행 가능
  • 파일 편집 도구 · MCP 서버 · 훅은 바깥에서 돎
  • Windows 기본 환경에선 동작 안 함 → WSL2

📦 dev container — Docker 안의 Claude

  • Claude Code 전체가 컨테이너 안에서 실행
  • 프로젝트 폴더만 붙이고, 명령은 상자 안에서
  • 공식 참조 구성: 나가는 통신을 막는 방화벽 스크립트
  • root 아닌 사용자 · 이 안에서만 권한 확인 생략 고려
  • 그래도 붙인 폴더는 고칠 수 있고, 믿는 저장소에만

처음엔 /sandbox(WSL2)로 가볍게, 팀이 같은 환경을 쓰거나 오래 혼자 돌릴 땐 dev container.

내장 샌드박스는 기본으로 꺼져 있고, 세션에서 /sandbox로 켜거나 설정 파일에서 켭니다. macOS는 Seatbelt, Linux · WSL2는 bubblewrap을 씁니다. dev container는 VS Code의 Dev Containers 기능으로 엽니다. Anthropic의 claude-code 저장소에 방화벽(init-firewall.sh)이 들어간 참조 구성이 있습니다. 공식 문서도 dev container 안이라도 믿을 수 있는 저장소에서만 쓰고, ~/.ssh 같은 호스트 비밀은 붙이지 말라고 안내합니다. 세부 옵션은 자주 바뀌니 문서를 확인하세요.

내 앱용 Dockerfile과 .dockerignore를 써줘.
python:3.11-slim, requirements 먼저 복사, root 아닌 사용자.
build → run(-p, -v out 폴더) 명령을 주고,

⌨️ B. 샌드박스 (직접)
docker run --rm -it --network none -v "${PWD}:/work:ro" python:3.11-slim bash
# 안에서: pip install requests  → 실패해야 정상
#        touch /work/x.txt       → 실패해야 정상 (ro)
#        rm -rf /tmp/*           → 상자 안만

✅ 완료 기준

  • 브라우저에서 localhost:8501로 상자 속 앱이 열린다
  • 컨테이너를 지웠다 다시 띄워도 out 폴더의 파일은 남아 있다
  • B에서 세 시도가 모두 상자 벽에 막힌 것을 확인했다

🧯 막히면

docker 명령이 "인식되지 않음"이면 터미널 덱의 PATH 장으로. 앱은 도는데 접속이 안 되면 -p와 0.0.0.0을 먼저 의심하세요.

25분. B에서 "실패해야 정상"인 실험이 핵심입니다. 막힌다는 걸 직접 확인해야 샌드박스를 믿고 쓸 수 있습니다. PowerShell에서는 ${PWD}, cmd에서는 %cd%.
