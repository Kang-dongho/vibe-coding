결론부터 — 이 세 줄이면 됩니다

터미널은 "어느 폴더에서" 명령을 실행하는 창입니다. 안 될 때 원인은 대부분 위치 아니면 PATH입니다.

  1. 1
    프롬프트 왼쪽이 지금 서 있는 폴더명령은 그 폴더를 기준으로 실행됩니다. 먼저 cd로 프로젝트 폴더에 들어갑니다.
  2. 2
    경로는 전체 주소(절대)와 여기서부터(상대) 두 가지"파일을 찾을 수 없음"은 대개 다른 폴더에서 상대 경로를 썼기 때문입니다.
  3. 3
    "명령을 찾을 수 없음" = PATH 목록에 그 프로그램이 없다PATH는 셸이 프로그램을 찾아보는 폴더 목록입니다. 고친 뒤엔 창을 새로 엽니다.

방금 친 명령 다시 불러오기.

Ctrl + C

실행 중인 것 멈추기. 복사가 아닙니다. 복사는 드래그 후 우클릭 또는 Ctrl+Shift+C.

PowerShell 기준 이름입니다. PowerShell은 ls · cp · mv · cat · rm을 별칭으로 받아 줍니다. Ctrl+C가 가장 많이 헷갈립니다. 서버가 돌고 있을 때 Ctrl+C를 누르면 서버가 꺼집니다. 서버를 켜 둔 채로 다른 명령을 치려면 터미널을 하나 더 엽니다(VS Code의 + 버튼).

프로그램이 몰래 읽는 메모 쪽지

이 터미널 창에 붙은 쪽지들
PATH프로그램 찾을 폴더 목록
HTTPS_PROXY사내 프록시 주소
DB_URL앱이 붙을 DB 주소
API_KEY비밀 — 코드에 쓰지 않는 이유
import os
url = os.environ["DB_URL"]   # 쪽지를 읽음 — 코드엔 주소가 없다
# PowerShell — 이 창에서만, 창 닫으면 사라짐
$env:DB_URL = "sqlite:///data/test.db"
$env:DB_URL                # 확인

# bash · zsh
export DB_URL="sqlite:///data/test.db"

# 매번 치기 싫으면 → .env 파일 (git에는 올리지 않음)
DB_URL=sqlite:///data/test.db

왜 굳이 쪽지로?

같은 코드를 내 PC · 서버 · 컨테이너에서 설정만 바꿔 돌리기 위해서. 비밀도 코드 밖에 둡니다.

환경변수는 그 창(과 거기서 실행한 프로그램)에만 붙는 쪽지입니다. 다른 창에서 설정한 값은 보이지 않습니다 — "아까 설정했는데 왜 없지?"의 원인. .env 파일은 python-dotenv 같은 라이브러리가 읽어서 쪽지로 붙여 줍니다. Docker 덱에서 같은 개념이 -e 옵션으로 다시 나옵니다.

못 찾으면

끝까지 뒤져도 없으면 "인식되지 않습니다 / command not found". 설치 여부가 아니라 목록에 있느냐의 문제.

먼저 찾은 것이 이긴다

파이썬이 두 개 깔려 있으면 위에 있는 것이 실행됩니다. "패키지 깔았는데 없다"의 단골 원인.

강조 표시가 위에서부터 내려가며 하나씩 확인하는 애니메이션입니다. 세 번째에서 찾으면 나머지는 보지도 않습니다. PATH는 결국 폴더 이름을 세미콜론(;)으로 이어 붙인 긴 글자 한 줄입니다(macOS·Linux는 콜론).

Windows 단골 함정

WindowsApps의 python.exe는 진짜 파이썬이 아니라 스토어로 안내하는 바로가기입니다. 진짜 파이썬 폴더가 PATH에서 그보다 위에 있어야 합니다.

  • 1설치할 때 "Add python.exe to PATH" 체크가장 쉬움
  • 2Windows 검색 → "시스템 환경 변수 편집" → Path → 위로 이동직접 수정
  • 3설정 → 앱 실행 별칭 → python 끄기스토어 바로가기
  • !고친 뒤 터미널 · VS Code를 새로 열기안 하면 그대로

Windows엔 py 런처도 있습니다. py -3.11 app.py처럼 버전을 골라 실행합니다.

마지막 줄이 가장 중요합니다. PATH는 창을 열 때 한 번 읽습니다. 이미 열린 창은 옛 목록을 들고 있어서, 고쳐도 "여전히 안 되네"가 됩니다. 회사 PC는 시스템 환경 변수 수정 권한이 없을 수 있습니다. 그때는 "사용자 변수" 쪽 Path를 고칩니다.

4번에서 하나가 "찾을 수 없음"이면 성공입니다 — 그게 바로 오늘의 PATH 문제입니다. 결과를 AI에게 붙이고 "PATH에 추가하는 법"을 물어보세요.

15분. 명령 하나하나보다 "결과를 읽는 것"이 목표입니다. 6번이 환경변수의 핵심 — 창마다 따로입니다.
정리

오늘 가져갈 습관 세 가지

1. 명령 전에 프롬프트 왼쪽을 본다

지금 서 있는 폴더가 모든 상대 경로의 출발점입니다.

2. "찾을 수 없음"엔 Get-Command

어느 프로그램이 실행되는지 확인하고, PATH를 고쳤으면 창을 새로 엽니다.

3. 설정과 비밀은 쪽지로

주소 · 키는 코드가 아니라 환경변수 · .env에. AI의 삭제 명령은 대상 경로부터 봅니다.
